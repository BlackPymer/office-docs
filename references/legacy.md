# Legacy-форматы и конвертации

## Обвязка

```bash
SK=~/.config/opencode/skills/office-docs
$SK/scripts/office_convert.py вход.формат выход.формат
```

Формат определяется **по расширению выхода**. Движок — LibreOffice (headless), поэтому поддержано всё, что он открывает.

## Таблица направлений

| Направление | Как | Качество |
|---|---|---|
| `.doc → .docx` | office_convert | ✅ текст, таблицы, стили, картинки; проверить надо разбивку строк и колонтитулы |
| `.ppt → .pptx` | office_convert | ⚠️ анимации/переходы теряются, шрифты подставляются; рендерить и сравнивать |
| `.xls → .xlsx` | office_convert | ✅ формулы и данные; проверить именованные диапазоны и диаграммы |
| `.docx/.pptx/.xlsx → .pdf` | office_convert | ✅ основной способ «сдать в PDF»; шрифты должны стоять на машине |
| `.docx → .md` | office_convert (pandoc) | ✅ заголовки, таблицы, картинки (как ссылки) |
| `.rtf/.html/.odt/.epub → .docx` | office_convert | ✅/⚠️ по вёрстке |
| `.pdf → .html` | office_convert | ⚠️ картинками по объектам, текст вынимается; для извлечения текста лучше `markitdown f.pdf` или `pdf_tool.py text` |
| `.md → .pdf` | pandoc → docx → office_convert | ✅ (сам pandoc в PDF требует LaTeX, которого нет) |

### Чего LibreOffice НЕ конвертирует (проверено на этой сборке)

Формат определяется по расширению **выхода**, и если нужного экспорта у исходного
документа нет, возвращается `Error: no export filter`. Это не баг скилла:

| Направление | Результат |
|---|---|
| `.pdf → .docx`, `.pptx`, `.odt`, `.odp`, `.xlsx`, `.txt` | ❌ `no export filter` — PDF открывается как **Draw**-документ, а у него нет экспорта в Writer-форматы |
| `.pdf → .html`, `.pdf → .pdf` | ✅ работают (Draw умеет их) |
| `.docx → .pptx`, `.docx → .xlsx` | ❌ кросс-конвертации между современными форматами не существует |
| `.pptx → .docx`, `.pptx → .txt`, `.pptx → .odt` | ❌ |
| `.xlsx → .docx`, `.xlsx → .txt`, `.xlsx → .csv` | ❌ |

Рабочие направления в эту сторону (проверены): `.docx → .pdf/.odt/.html/.txt/.md`,
`.pptx → .pdf/.odp/.html`, `.xlsx → .pdf/.ods/.html`.

Из этого следует правило: **PDF — тупиковый формат для редактирования**. Получили
PDF и нужно продолжить работу в Word — значит, исходника в Word уже нет; извлекайте
текст (`pdf_tool.py text`, `markitdown`) и создавайте новый документ заново,
а не пытайтесь отконвертировать обратно.

## Правила

1. **Всегда конвертируйте в копию** и сверяйте результат рендером:
   ```bash
   $SK/scripts/office_convert.py old.doc new.docx
   $SK/scripts/render_check.py old.doc old     # старый в картинки
   $SK/scripts/render_check.py new.docx new    # новый в картинки
   # посмотрите оба набора страниц: текст должен совпасть, вёрстка — тоже
   ```
2. **Что обычно теряется при `.doc/.ppt`:** анимации, шрифты (заменяются установленными — кириллица может перекомпоноваться), точные отступы в колонтитулах, некоторые OLE-объекты, поля с результатами (TOC покажет «обновите поле»).
3. **`.ppt → .pptx` проверяйте постранично**: текстовые блоки «уплывают», если в оригинале использованы нестандартные шрифты — их на машине нет, LibreOffice подставляет похожие и вёрстка едет.
4. **Legacy-файл — только источник.** Правки делайте в современном формате после конвертации, а на `.doc` не отдавайте результат.
5. Если конвертер пишет `Файл не создан` — направление не поддерживается фильтром; оставьте задачу в исходном формате и объясните пользователю.

## Проверка конвертации

```bash
$SK/scripts/validate.py new.docx --soffice   # PASS?
```
Плюс текстовая сверка содержимого: `pandoc old.doc -t gfm` vs `pandoc new.docx -t gfm` (для `.ppt` — `pptx_outline.py` vs `markitdown old.ppt`).
